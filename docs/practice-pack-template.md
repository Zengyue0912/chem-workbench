# 同步练习 · 组员投稿题包模板

> 本文档说明如何向高中化学 3D 工作台「同步练习」投稿题目。格式依据为仓库现有代码
> `js/inline-09-studio.js` 中的内置题库与校验逻辑（见文末「格式依据」），不是凭想象编造的格式。
> 投稿文件为 JSON（或含题包数据块的 Markdown），请把写好的文件交给仓库维护者合并。

---

## 一、题包对象字段（chem-practice/2）

题包是一个 JSON 对象，顶层字段如下：

| 字段 | 类型 | 必填 | 取值 / 限制 |
|---|---|---|---|
| `schema` | 字符串 | 是 | 必须恰好为 `"chem-practice/2"`，否则导入被拒绝 |
| `id` | 字符串 | 是 | 1–64 个字符，只能含字母、数字、`_`、`.`、`-`；不能是 `__proto__`、`constructor`、`prototype`。建议用投稿人前缀，如 `zhangsan-acid-base` |
| `version` | 字符串 | 是 | 与 `id` 相同的字符规则，如 `"1.0"` |
| `title` | 字符串 | 是 | 非空，最长 120 字符 |
| `description` | 字符串 | 是 | 非空，最长 1200 字符，写清题包范围与原创声明 |
| `topics` | 字符串数组 | 是 | 1–20 项，每项非空、最长 80 字符；每道题的 `topic` 必须取自此列表 |
| `questions` | 题目对象数组 | 是 | 1–300 题；每包最多 300 题 |
| `sources` | 对象数组 | 否 | 最多 8 项；每项含 `title`（非空，最长 160 字符）与 `url`（必须以 `https://` 开头，最长 500 字符）。用于标注参考资料来源 |

题包文本总长度不得超过 1,000,000 字符；通过文件导入时文件不得超过 2 MB。

内置题包的章节示例（`topics`）：`物质与反应`、`元素及其化合物`、`结构与有机`、`反应原理`、`定量分析`、`实验探究`。投稿可沿用这些章节，也可在自己题包的 `topics` 里另行定义，但题目 `topic` 必须与本包 `topics` 一致。

## 二、题目对象字段

| 字段 | 类型 | 必填 | 取值 / 限制 |
|---|---|---|---|
| `id` | 字符串 | 是 | 与题包 `id` 相同的字符规则；**同一题包内必须唯一**。建议用投稿人前缀，如 `zhangsan-s01` |
| `topic` | 字符串 | 是 | 必须在题包 `topics` 列表中，否则导入失败 |
| `title` | 字符串 | 是 | 非空，最长 160 字符，如 `离子共存` |
| `stem` | 字符串 | 是 | 题干，非空，最长 6000 字符 |
| `type` | 字符串 | 是 | 四选一：`single`（单选）、`multi`（多选）、`fill`（填空）、`experiment`（实验大题） |
| `points` | 整数 | 是 | 1–50 的整数。`fill` / `experiment` 时必须等于各小题 `points` 之和 |
| `options` | 字符串数组 | `single` / `multi` 必填 | 2–8 项，每项非空、最长 1500 字符；`fill` / `experiment` 不使用 |
| `answer` | 见下 | `single` / `multi` 必填 | `single`：整数下标，范围 `0` 至 `选项数 − 1`（0 表示 A）；`multi`：下标数组，非空、不超过选项数，校验时会自动去重并排序 |
| `parts` | 小题对象数组 | `fill` / `experiment` 必填 | 1–12 个小题；`single` / `multi` 不使用 |
| `analysis` | 字符串（见第三节） | 是 | 解析，非空，最长 6000 字符（字符串形式）；结构化对象形式见第三节说明 |
| `source` | 字符串 | 是 | 非空，最长 300 字符；原创写 `原创同步练习`，改编须注明改编来源 |
| `level` | 字符串 | 是 | 非空，最长 40 字符；现有题库使用 `巩固`（基础巩固）与 `综合`（综合应用），投稿请沿用这两个取值 |

### 小题对象（`parts` 的每一项）字段

| 字段 | 类型 | 必填 | 取值 / 限制 |
|---|---|---|---|
| `id` | 字符串 | 是 | 与题目 `id` 相同的字符规则；**同一题目内必须唯一**，常用 `a`、`b`、`c`…… |
| `kind` | 字符串 | 是 | 三选一：`numeric`（数值）、`text`（文本）、`manual`（开放作答，需人工/量规核对） |
| `prompt` | 字符串 | 是 | 小题题干，非空，最长 2000 字符 |
| `points` | 整数 | 是 | 1–50 的整数；各小题之和须等于题目 `points` |
| `unit` | 字符串 | 否 | 单位，如 `g`、`mol/L`、`mL`、`%`；最长 100 字符，无单位填 `""` |
| `tolerance` | 数字 | `numeric` 必填 | 容差，必须是有限数字，范围 0–1000。判分规则：学生答案与标准答案的绝对误差 ≤ `tolerance` 即正确。`tolerance: 0` 表示必须精确相等，适用于整数答案（如原子数） |
| `answer` | 见下 | `numeric` / `text` 必填 | `numeric`：必须是 JSON 数字（如 `2.925`，不能写成字符串）；`text`：参考答案字符串数组，1–20 项，每项最长 1000 字符，可列多种等价写法（如 `["Cl", "氯"]`）；`manual`：填 `null` |
| `rubric` | 字符串 | `manual` 必填 | 核对量规，最长 4000 字符；`manual` 小题必须非空，写清得分要点。`numeric` / `text` 小题可填 `""` |

判分补充说明（来自判分逻辑 `grade` / `part`）：

- 多选：全对得满分；只选部分正确项且无错选得一半分（向下取整）；错选不得分。
- 文本填空：作答与参考答案比对时会自动做规范化处理——全角转半角、去掉全部空白、下标数字（如 `₂`）转普通数字、`⁺` 转 `+`、`⁻`/`−` 转 `-`。因此参考答案里写 `C2H6O` 与 `C₂H₆O` 是等价的，列一种即可，多列也无妨。
- 数值填空：学生可输入科学计数法；判分时在 `tolerance` 基础上还有极小的浮点误差宽容。

## 三、解析（`analysis`）格式

### 1. 字符串形式（老格式，当前代码可直接使用）

`analysis` 写成一个字符串，讲清解题思路、关键判断与易错点。现有 60 道内置题全部使用这种形式。
示例：`"强酸性排除 HCO₃⁻、OH⁻；无色条件排除大量 Fe³⁺。第一组在给定条件下无相互消耗的反应。"`

### 2. 结构化对象形式（v2.4 推荐格式）

为把解析写得更完整、更统一，v2.4 推荐使用结构化对象形式：

```json
"analysis": {
  "focus": "考什么：本题考查的知识点 / 能力要求，一句话。",
  "approach": "怎么想：解题的整体思路 / 切入点，一两句话。",
  "steps": [
    "第一步：……",
    "第二步：……",
    "第三步：得出结论……"
  ],
  "pitfalls": "易错点：最容易错的地方，以及错因。"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `focus` | 字符串 | 考什么：知识点与能力要求 |
| `approach` | 字符串 | 怎么想：解题思路与切入点 |
| `steps` | 字符串数组 | 分步详解，每一步一个字符串，按顺序写清推导过程 |
| `pitfalls` | 字符串 | 易错点：常见错误与错因提醒 |

> ⚠️ **重要提示：结构化解析目前尚未被校验器接受。**
> 当前代码的校验函数（`js/inline-09-studio.js` 约第 148 行）要求 `analysis` 必须是字符串，
> 结构化对象会在导入时被拒绝，页面渲染也是按字符串显示的。
> 因此投稿时请这样处理：
>
> - **投稿前请先向仓库维护者确认**：校验器是否已升级为支持结构化解析。
> - 若已升级：按上面的结构化对象形式投稿。
> - 若尚未升级：请把结构化内容合并成一个字符串投稿（按「考什么 / 怎么想 / 分步详解 / 易错点」四段顺序写成一段文字即可），
>   同时可把结构化版本一并附在文件末尾的注释说明里供维护者参考。JSON 本身不支持注释，
>   如需附带说明请另写一个文本文件，不要把注释写进 JSON。

## 四、完整示例题（单选题，可直接复制改写）

下面是一个完整的单选题示例，带结构化解析。投稿时请按第三节的提示确认解析形式：
若校验器尚未升级，把 `analysis` 对象改写成字符串即可，其余字段不变。

```json
{
  "schema": "chem-practice/2",
  "id": "zhangsan-acid-base",
  "version": "1.0",
  "title": "酸碱与盐 · 投稿练习",
  "description": "组员张三投稿的酸碱与盐原创练习，共 1 题，单选题。",
  "topics": ["物质与反应"],
  "questions": [
    {
      "id": "zhangsan-s01",
      "topic": "物质与反应",
      "title": "酸碱中和的判断",
      "stem": "向 10 mL 0.1 mol/L 盐酸中逐滴加入 0.1 mol/L NaOH 溶液，恰好完全中和时消耗 NaOH 溶液的体积是？",
      "type": "single",
      "points": 4,
      "options": [
        "5 mL",
        "10 mL",
        "20 mL",
        "无法确定"
      ],
      "answer": 1,
      "analysis": {
        "focus": "考查酸碱中和反应的计量关系：HCl 与 NaOH 按 1∶1 反应。",
        "approach": "先算盐酸的物质的量，再按 1∶1 的计量比算出所需 NaOH 的物质的量，最后换算体积。",
        "steps": [
          "第一步：n(HCl) = 0.1 mol/L × 0.010 L = 0.0010 mol。",
          "第二步：HCl + NaOH = NaCl + H₂O，计量比 1∶1，故 n(NaOH) = 0.0010 mol。",
          "第三步：V(NaOH) = 0.0010 mol ÷ 0.1 mol/L = 0.010 L = 10 mL，选 B。"
        ],
        "pitfalls": "易错点：误以为酸碱浓度相同则体积一定相等——只有计量比为 1∶1 且浓度相等时才成立；若换成 H₂SO₄ 与 NaOH（计量比 1∶2），体积就不同了。"
      },
      "source": "原创同步练习",
      "level": "巩固"
    }
  ]
}
```

> 同题的字符串形式解析（校验器未升级时使用）：
>
> `"analysis": "考什么：酸碱中和反应的计量关系，HCl 与 NaOH 按 1∶1 反应。怎么想：先算盐酸的物质的量，再按计量比算 NaOH 的量，最后换算体积。分步：① n(HCl)=0.1×0.010=0.0010 mol；② n(NaOH)=0.0010 mol；③ V=0.0010÷0.1=0.010 L=10 mL，选 B。易错点：只有计量比 1∶1 且浓度相等时体积才相等；换成 H₂SO₄ 与 NaOH（1∶2）体积就不同。"`

## 五、投稿校验规则清单

提交前请逐项自查，全部通过再交给维护者：

### 格式与结构

- [ ] 文件是合法 JSON（可用任意 JSON 校验工具检查），顶层 `schema` 恰好为 `"chem-practice/2"`。
- [ ] 题包 `id`、`version` 只含字母、数字、`_`、`.`、`-`，长度 1–64；`id` 建议带投稿人前缀（如 `zhangsan-...`），避免与他人投稿冲突。
- [ ] `title`、`description` 非空且未超长（120 / 1200 字符）；`topics` 有 1–20 项。
- [ ] 题目总数 1–300 题；题包文本不超过 1,000,000 字符。
- [ ] 每道题的 `topic` 都在题包 `topics` 列表中。
- [ ] 每道题的 `id` 在题包内唯一，建议带投稿人前缀（如 `zhangsan-s01`、`zhangsan-f02`）。

### 题目内容

- [ ] `type` 只能是 `single`、`multi`、`fill`、`experiment` 四者之一。
- [ ] `points` 是 1–50 的整数；`fill` / `experiment` 的总分等于各小题分值之和。
- [ ] 单选 / 多选：`options` 有 2–8 项；`answer` 下标不得越界（单选为 0 至选项数 − 1 的整数；多选为下标数组，非空且不超过选项数）。
- [ ] 填空 / 实验大题：`parts` 有 1–12 个小题；小题 `id` 在同一题内唯一；`kind` 只能是 `numeric`、`text`、`manual` 三者之一。
- [ ] `numeric` 小题：`answer` 必须是 JSON 数字（不能加引号写成字符串）；`tolerance` 必须是 0–1000 的有限数字，且与答案量级相配（例如答案 2.925 用 0.005，答案 0.001 用 0.00001；不要把容差设得比答案本身还大，也不要对需要精确相等的小题设过大的容差）。
- [ ] `text` 小题：`answer` 是 1–20 个参考答案字符串，已列出常见的等价写法。
- [ ] `manual` 小题：`answer` 为 `null`，且 `rubric` 非空，写清核对要点。
- [ ] `analysis` 必填：字符串形式非空且 ≤6000 字符；结构化形式须含 `focus`、`approach`、`steps`、`pitfalls` 四个字段（投稿前先确认校验器是否已支持结构化形式，见第三节）。
- [ ] `source`、`level` 必填；原创写 `原创同步练习`，`level` 用 `巩固` 或 `综合`。

### 原创与来源

- [ ] **题干与选项不得抄袭教辅与真题原文**：不得照抄《必刷题》《五三》等教辅或高考真题的原文；题目须为原创，或在原有思路基础上实质性改写（改数据、改情境、改设问）并在 `source` 中注明来源。
- [ ] 解析须自己撰写，不得照抄教辅解析。
- [ ] 引用外部资料（如教材页码、公开教学资源）时，在题包 `sources` 中注明标题与 `https://` 链接；不要编造不存在的链接。

### 自查方法

- **对照测试文件自查**：仓库的 `tests/practice-bank.test.js`（投稿校验测试，50 项）已建立，可对照其中的校验项逐项核对；也可以先按上面这份清单自查。
- **用工作台自测导入**：打开工作台「同步练习」→「导入题目」，选择文件或粘贴内容，点击「检查并导入」。导入失败会显示具体原因（如「答案索引越界」「总分与小题分值不一致」），且原题包不会被替换，可放心反复测试。注意：导入成功会替换当前题包，测试前请先用「导出当前题包」备份，或测试后用「恢复内置练习」还原。
- **数值题验算**：所有 `numeric` 答案请独立验算一遍（手算或用计算器），确认答案与容差无误。

## 六、投稿方式

1. 按本文档写好题包 JSON 文件，文件名建议用 `练习主题-投稿人.json`，例如 `酸碱与盐-张三.json`。
2. 按第五节的清单完成自查，尽量在工作台里实际导入测试一次。
3. **把 JSON 文件交给仓库维护者合并**（直接发给维护者即可）。维护者会复核格式与内容，通过后合并进题库并统一发布。
4. 投稿后若维护者反馈需要修改，请修改后重新提交完整文件（不要只发修改片段）。

> 本文档不提供投稿邮箱或投稿链接——请直接联系仓库维护者提交文件。
